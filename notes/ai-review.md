## 2. Core Architecture: Multi-Heuristic Tradeoff Engine + 5th BQ Table

### Why This Aligns Directly with the Judging Rubric
- **55% of the judging score** is **Impact & Insight (30 pts)** + **Rigor & Judgment (25 pts)** (`README.md`).
- The challenge explicitly states:
  > *"Vector search is a candidate generator, not an answer... Two viable recipients—do you send it to the bigger one, the closer one, or the one in the higher-need tract? There is no right answer and judges know it. They want to hear you choose on purpose."*

Instead of collapsing everything into a single black-box score, our agent acts as a **Multi-Heuristic Tradeoff Broker** that evaluates surviving candidates across **4 explicit heuristics**:

### A. The 4 Matching Heuristics (Post-Vector Search & Hard Constraint Filter)

First, **Hard Constraints** eliminate invalid candidates:
- Cold/frozen storage compatibility (`cold_storage`, `frozen_storage` vs. posting `storage_state`)
- Contradiction & decoy filtering (catching planted traps)
- Time clock feasibility (`pickup_window_hours <= hours_remaining`)
- Capacity check (`effective_available_pallets >= required_pallets`, or eligible for Load-Splitting)

Next, viable candidates are scored across **4 Heuristics**:
1. **Clock & Logistics Safety (`S_urgency`)**:
   - Safety margin (`hours_remaining - pickup_window_hours`), `refrigerated_transport = TRUE` (can self-collect without waiting for a volunteer driver), and `loading_dock` compatibility.
2. **Distance / Proximity (`S_distance`)**:
   - Straight-line distance (`ST_DISTANCE`) or drive-time estimate between Donor and Recipient coordinates.
3. **Community Equity & Need (`S_equity`)**:
   - Composite need score from `tract_demographics` (`poverty_rate`, `no_vehicle_rate`—crucial in Atlanta where 14.7% of households have no vehicle—and `assistance_rate`), combined with `weekly_households` and organization scale (`reported_income`).
4. **Diminishing Marginal Impact / Saturation (`S_freshness` from Table #5)**:
   - Evaluates recent deliveries in `a4i_food.match_history`. If a recipient just received a similar donation in the last 24–72 hours, their effective free capacity is reduced and their marginal equity impact for another drop decreases compared to an equally qualified pantry that hasn't received a delivery recently.

### B. Presenting Tradeoffs to the User
Rather than returning a single rigid ranking, the agent presents **Pareto-optimal match options** and explains the tradeoff:
- **Match Option 1 — Fastest / Closest Rescue (`SPEED_OPTIMAL`)**:
  - *Example:* 1.9 miles away, refrigerated van ready in 2 hours (4-hour safety margin on the clock), located in a moderate-need tract (14% poverty).
- **Match Option 2 — Maximum Community Impact Tradeoff (`EQUITY_OPTIMAL`)**:
  - *Example:* 5.4 miles away (+15 mins travel cost, still safely within the 6-hour spoilage window), located in a high-need tract (**35% poverty, 28% no-vehicle access**) with **0 produce deliveries in the past 14 days** (+65% higher marginal impact).
- **Match Option 3 — Backup / Split Option (`RESILIENCE_FALLBACK`)**:
  - Ready if Option 1 or 2 declines ("They said no" workflow).

### C. Schema & Role of the 5th Table: `a4i_food.match_history`
| Column | Type | Purpose |
|---|---|---|
| `match_id` | `STRING` | Unique ID for the match event |
| `matched_at` | `TIMESTAMP` | When the match was proposed/completed |
| `posting_id` | `INTEGER` | Reference to `surplus_postings.posting_id` |
| `track` | `STRING` | `RETAIL`, `FARM`, or `ESSENTIALS` |
| `food_category` | `STRING` | Category of food/item (`produce`, `dairy`, `bread`, `formula`, `diapers`, etc.) |
| `donor_name` | `STRING` | Donor organization / store / farm |
| `recipient_id` | `INTEGER` | Reference to `recipients.recipient_id` |
| `recipient_name` | `STRING` | Organization name |
| `pallets_matched` | `FLOAT` | Pallets allocated (reduces same-day remaining capacity) |
| `distance_miles` | `FLOAT` | Distance between donor and recipient |
| `heuristic_mode` | `STRING` | Which tradeoff priority won (`EQUITY_OPTIMAL`, `SPEED_OPTIMAL`, `BALANCED`, `LOAD_SPLIT`) |
| `status` | `STRING` | `COMPLETED`, `IN_TRANSIT`, `ACCEPTED`, or `DECLINED` |
| `decline_reason` | `STRING` | Optional reason if `status = 'DECLINED'` (e.g., `"Cooler full today"`) |
| `tract_geo_id` | `STRING` | Recipient's census tract `geo_id` |
| `tract_poverty_rate` | `FLOAT` | Snapshot of tract poverty rate for fast Equity Auditing |
| `tract_no_vehicle_rate` | `FLOAT` | Snapshot of tract no-vehicle rate for fast Equity Auditing |

**Three High-Value Capabilities Unlocked by `match_history`:**
1. **Dynamic Impact & Capacity Adjustment:** Recent `COMPLETED`/`IN_TRANSIT` deliveries reduce a pantry's available pallet space today and shift marginal equity weight toward underserved pantries.
2. **"They Said No" Graceful Re-Routing:** If a Manager logs that Top Match #1 declined, the agent writes `DECLINED` to `match_history`, excludes them from the active round, and promotes the next match with a ready-to-send outreach message.
3. **Live Equity Audit:** At any time, the Manager can ask *"Did our food go where the need is, or where the loading docks are?"* and the agent compares `match_history` averages against Atlanta's metro baseline (`20.2%` poverty, `14.7%` no-vehicle).

## 3. Personas & Tracks Breakdown

### Three Personas
1. **Donor Persona (Grocers, Farms, Distributors)**:
   - Submits messy free-text offers (e.g., *"10 crates of spinach, harvested yesterday, needs cold storage"*).
   - Agent parses quantity/pallets, storage state, and donor deadline, resolves real shelf life against USDA FoodKeeper (`shelf_life`), and immediately previews top impact matches.
2. **Recipient Persona (Pantries, Shelters, Soup Kitchens, Clinics, Diaper Banks)**:
   - **Conversational Intake & Profile Updater:** Onboards new pantries or updates current capacity/hours in natural language, automatically writing to `recipients` and embedding into `recipient_embeddings`.
   - Can accept or decline incoming match offers.
3. **Manager / Coordinator Persona**:
   - Views the live Match Brief with **Multi-Heuristic Tradeoff comparisons** (Speed/Distance vs. Equity/Need vs. Recent Saturation).
   - Triggers **Load Splits** for massive farm surplus loads, handles **"They Said No"** re-routing, dispatches outreach messages, and runs the **Metro Equity Audit**.

### Three Tracks
- 🛒 **Track 1: Retail & Grocer Rescue (`RETAIL`)** — Short clock (4–24 hours), mixed perishables, strict cold-storage filtering.
- 🚜 **Track 2: Farm & Agricultural Surplus (`FARM`)** — Massive single-item volume (e.g., 5 tons of potatoes / 30 bins of squash), requires **Load-Splitting** across multiple pantries or **Hub-and-Spoke** pairing (Regional Warehouse + Mobile Pantry).
- 🍼 **Track 3: Critical Non-Food Essentials (`ESSENTIALS`)** — Infant formula, diapers, medical nutrition; requires strict handling/expiry verification and specialized recipients (`community_clinic`, `diaper_bank`, `shelter_kitchen`).

## 4. Key Differentiators to Set Our Agent Apart

1. **Explicit "Guardrail Transparency" on Planted Traps (Huge Rubric Booster)**:
   - The corpus contains **9 planted teaching cases** (`profile_source = 'planted'`), including:
     - **`Greenline Community Pantry`** (*Near-Miss Decoy*): Ranks #1 semantically for fresh greens, but has `cold_storage = 'none'`.
     - **`Harborview Neighbors Trust`** (*Contradiction*): Claims a walk-in freezer in one sentence and *"a single shelf in a shared cupboard and no freezer at present"* in the next.
     - **`Cedar Street Produce Alliance` & `Maple Street Produce Alliance`** (*Genuine Ties*): Identical operational profiles that require our multi-heuristic tie-breaker (distance, tract equity, and recent donation history).
   - **Action:** Every Match Brief will include a **"Safety & Capacity Guardrails: Why Top Semantic Matches Were Filtered"** callout showing that our agent caught `Greenline` and `Harborview` rather than blindly trusting vector similarity.

2. **Conversational Recipient Intake with Live Vector Re-Embedding**:
   - Explicitly named in `README.md` as *"The add-on we'd build if we had another four hours."*
   - A new Atlanta pantry can register via chat, get embedded on the fly with `AI.EMBED`, and immediately appear in a live match during the demo.

3. **Multi-Recipient Load Splitting & Hub-and-Spoke Routing (Farm Track)**:
   - When a posting exceeds any single high-need pantry's `max_pallets` (like the 5 tons of potatoes), the agent automatically proposes a **Split Match Brief** across 2–3 compatible recipients (or pairs a regional hub with a mobile pantry) and drafts coordinated messages for each.

4. **Semantic USDA Shelf-Life Lookup + Optional OpenFDA Recall Check**:
   - Uses semantic/keyword fallback over `shelf_life` (`product_name`, `product_subtitle`, `keywords`) so free-text Donor postings like *"spinach"* resolve to `"Lettuce (Spinach)"` automatically.
   - Optional tool to query the public OpenFDA Food Enforcement API (`api.fda.gov/food/enforcement.json`) to verify infant formula / retail lots are not under active recall before brokering.

   - Build Python ADK tools for:
     - `evaluate_surplus_matches`: Runs `VECTOR_SEARCH`, applies hard storage/clock/contradiction filters, joins `match_history` saturation, and returns ranked candidates under `BALANCED`, `EQUITY_OPTIMAL`, `SPEED_OPTIMAL`, plus `LOAD_SPLIT` and eliminated decoys.
     - `record_match_decision`: Logs `ACCEPTED`, `COMPLETED`, or `DECLINED` into `a4i_food.match_history` and triggers instant re-routing on decline.
     - `onboard_or_update_recipient`: Conversational intake tool that inserts/updates `recipients` and embeds into `recipient_embeddings`.
     - `run_equity_audit`: Compares `match_history` distributions against Atlanta metro census tract baselines.
3. **Step 3 — Multi-Persona ADK Agent, MCP Integration & Cloud Run Deployment**:
   - Wire the ADK agent with clear persona instructions (Donor, Recipient, Manager) and Match Brief formatting, integrate the MCP server, and deploy to Cloud Run.
